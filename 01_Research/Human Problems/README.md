## Description

The Human Problems Repository is the foundational research asset of VedMoulya. It systematically documents the most common and impactful human problems related to learning, careers, business, freelancing, execution, and sustainable livelihoods. Every product feature, every AI agent behavior, and every platform decision must trace back to a validated human problem documented here.

---

## Purpose

1. **Empathy at scale** — Ensure every product decision is grounded in real human needs, not assumptions.
2. **Opportunity identification** — Surface high-impact problems that VedMoulya can solve through its Human Execution OS.
3. **Product validation** — Provide a single source of truth that product teams reference when prioritizing features.
4. **AI alignment** — Guide AI agent training and behavior by grounding them in validated human pain points.
5. **Research continuity** — Maintain institutional knowledge about user needs as the team grows.

## Why This Research Exists

VedMoulya's mission is to _empower every determined individual to build a sustainable livelihood through knowledge, execution, and intelligent technology_. To fulfill this mission, we must deeply understand the problems people face when trying to:

- Learn new skills effectively
- Build meaningful careers
- Start and grow businesses
- Succeed as freelancers
- Execute consistently on their goals
- Create sustainable income streams
- Adapt to technological change (especially AI)

Without this understanding, we risk building solutions that solve problems nobody has. The Human Problems Repository is our hedge against that risk.

## How It Will Be Maintained

| Activity                      | Frequency  | Responsible                  |
| ----------------------------- | ---------- | ---------------------------- |
| New problem discovery         | Continuous | Research Team                |
| Problem validation            | Weekly     | Research Team                |
| Problem prioritization        | Monthly    | Product + Research           |
| Repository review & cleanup   | Quarterly  | Principal Research Architect |
| Cross-reference with features | Per sprint | Product Team                 |

**Process:**

1. Discover → Capture in Problem Repository using the Problem Template
2. Validate → Apply the Problem Validation Framework
3. Prioritize → Score using the Problem Prioritization Framework
4. Reference → Link to product features during PRD creation
5. Iterate → Update as new evidence emerges

## Feature Validation Policy

**Every feature shipped on VedMoulya MUST reference at least one validated problem from this repository.**

This is not optional. The Problem ID must be cited in the feature's PRD, and the validation evidence must support the feature's design decisions. Features that cannot trace back to a validated problem must be flagged for review.
