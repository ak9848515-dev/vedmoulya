## 4. What SPRINT-030 explicitly will NOT do

- **No new engine**: no Brain / Memory / Execution / Authorization / Budget / Scheduler / Notification / Voice / Learning / AI-Agent engine.
- **No autonomous execution**: scheduled research/recommendation/discovery are allowed; sensitive execution stays behind the existing approval authority (LEVEL 3) and never jumps levels.
- **No fabricated health/cost/privacy**: UNKNOWN stays UNKNOWN; health is only ever OBSERVED; cost is only ever MEASURED or policy-checked.
- **No hardcoded providers**: the fabric speaks capability ids + candidate evidence, never provider business logic.
- **No multi-tenant data plane**: owner isolation remains strict (stores keyed by owner); the company/workspace hierarchy is scoped to FUTURE (SPRINT-031+) — the fabric's cost policy already accepts a `workspaceId` so the model does not need redesign.

## 5. Architecture decision

New **`packages/intelligence-fabric`** — a composition package (same pattern as `packages/voice` and `packages/proactive`): types → contracts (narrow ports) → domain (deterministic policies/ledgers) → application (composition seam) → infrastructure (in-memory + Postgres stores). Gateway `fabric.*` namespace (auth + rate tier + IDOR). The SPRINT-029 deferred cadence is wired into the existing `SchedulerCadenceDriver` as a proactive refresh port (research/recommend only).
